# services

Everything that talks to the outside world. The clients are built from `config/services.ts`, so no URL or model name is written here.

- `index.ts` builds the clients. `createClients("upstream")` uses the real URLs and adds the keys, for Node scripts. `createClients("proxy")` uses the dev server's prefixes and no keys, for the browser. `resolveBackend` turns one entry of `llmBackends` into a URL and headers. The NLU bench also uses it to reach disabled backends.
- `llm.ts` is one LLM client over several OpenAI-compatible backends. `json` tries them in order, with `prefer` putting named ones first, and returns the first answer that parses as a JSON object. Each call reports which backend answered and which ones failed before it and why (`LlmAnswer`). The debug view prints this.
- `embeddings.ts` talks to Ollama. `movieText` is the exact text a movie is embedded as: title, year, genres, overview and keywords. Changing it re-embeds the whole catalogue on the next run, because the text hashes no longer match. `createEmbedQuery` embeds wish and avoid texts with the model's query instruction. `hash53` is the short text hash the vector store uses to notice a changed text.
- `tmdb.ts` is the TMDB client. `pool` returns every movie that matches the Phase 1 filters from `/discover/movie`. TMDB stops at page 500, so the walk halves the range of release years until each half fits. Results are sorted by release date rather than popularity, so pages do not shift while they are read. `details` fetches the runtime, directors, top cast, US rating and keywords in one call. `buildDiscoverParams` turns `SearchCriteria` into query parameters. A 429 is retried after a short wait.
- `catalogue.ts` is the local copy of TMDB in `.cache/`, Node only. It keeps a record, keywords and a vector for every movie with at least `settings.catalogue.minVotes` votes.
  - `createNodePool` loads tonight's pool for the typed chat and for the dev server, which passes it on to the browser. Without streaming services the pool comes from the local copy (`localPool`), plus a small TMDB walk over the years since the last top-up. With streaming services it walks TMDB, because availability changes every week. The same happens when the filters are wider than what the copy holds. Either way the result is filtered again on runtime and rating, since TMDB's own runtime filter is loose.
  - `ensureVectors` is the one place where movies become vectors. It fetches details for new movies, embeds every text whose hash changed, and saves both.
  - `loadVectorStore` keeps the vectors in a `.bin` of Float32 rows with a `.json` index, loaded whole into memory. Every save goes through a temp file and a rename, so a crash never leaves half a file.
